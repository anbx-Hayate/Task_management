# Task_management

田中颯のタスクを管理するためのリポジトリーです。

単なる ToDo 管理ではなく、**背景理解 → タスク分解 → 進捗管理 → 工数管理 → 振り返り** までを GitHub Projects と Issue / Sub-Issue で一貫管理します。

## クイックスタート

1. [Projects セットアップ手順](docs/PROJECTS_SETUP.md) に従い、カスタムフィールドとラベルを作成する
2. **Issues → New issue** から「大タスク」テンプレートで最初のタスクを作成する
3. 大タスクから中タスク → 小タスクへ Sub-Issue で分解する
4. Projects ボードで日々の進捗を管理する

## タスク階層

```
大タスク（親 Issue）
├── 中タスク（Sub-Issue）
│   ├── 小タスク（Sub-Issue）
│   └── 小タスク（Sub-Issue）
└── 中タスク（Sub-Issue）
    └── 小タスク（Sub-Issue）
```

| 階層 | Issue の扱い | テンプレート | 管理の要点 |
|------|--------------|--------------|------------|
| 大タスク | 親 Issue | `大タスク` | 背景・目的・届け先・成功状態を記載 |
| 中タスク | 大タスクの Sub-Issue | `中タスク` | 成果物単位の分解 |
| 小タスク | 中タスクの Sub-Issue | `小タスク` | 実作業単位。工数・評価軸を入力 |

## 大タスクで管理する必須項目

| 項目 | 内容 |
|------|------|
| ① 背景・目的 | なぜこのタスクを行うのか |
| ② 届け先 | 誰に成果物を届けるのか |
| ③ 成功状態 | 相手がどのような状態になれば成功か（相手のゴール） |

## 進捗管理（Status）

| 状態 | 意味 |
|------|------|
| 未着手 | まだ作業を開始していない |
| 着手中 | 現在作業中 |
| 完了 | 作業完了 |
| 保留 | 一時停止（理由を Issue コメントに記載） |

## タスク評価軸

各タスク（主に小タスク）に以下の属性を設定します。

| 軸 | 選択肢 | 用途 |
|----|--------|------|
| インパクト | 大 / 中 / 小 | 優先順位判断 |
| 時間負荷 | すぐ終わる / 普通 / 重い | 午前（頭を使う作業）への割り当て |
| 気軽さ | 楽 / 普通 / 気重 | 午後（機械的作業）への割り当て |

## 工数管理

| 項目 | 型 | 例 |
|------|-----|-----|
| 予想時間 | Single select | 15分 / 30分 / 1時間 / 3時間 |
| 実時間（分） | Number | 45 / 90 / 180 |
| 予想との差異理由 | Single select | 調査時間が増加 / 手戻り発生 / レビュー対応発生 / 想定以上に難しかった |

## 運用ルール

### 9ステップフロー

```
1. 大タスク作成
2. 背景・目的記載
3. 中タスク分解
4. 小タスク分解
5. 予想時間入力
6. 作業実施
7. 実時間入力
8. 差異理由記録
9. 振り返り実施
```

### ステップ別の操作

| ステップ | 操作 |
|----------|------|
| 1. 大タスク作成 | Issue テンプレート「大タスク」で Issue 作成 |
| 2. 背景・目的記載 | ①②③④ を本文に記入。`届け先` フィールドも設定 |
| 3. 中タスク分解 | 大タスクから Sub-Issue を作成。本文の中タスク一覧にリンク追記 |
| 4. 小タスク分解 | 各中タスクから Sub-Issue を作成（15分〜3時間で完了する粒度） |
| 5. 予想時間入力 | 小タスクに `予想時間`・`インパクト`・`時間負荷`・`気軽さ` を設定 |
| 6. 作業実施 | `Status` を「着手中」に変更。午前＝重い作業、午後＝楽な作業 |
| 7. 実時間入力 | 完了時に `実時間（分）` を記入、`Status` を「完了」に変更 |
| 8. 差異理由記録 | 予想と実時間に差があれば `予想との差異理由` を選択 |
| 9. 振り返り実施 | 大タスク本文の振り返り欄を記入。`振り返り済み` を「実施済み」に |

### 日次運用

| タイミング | やること |
|------------|----------|
| 朝 | `時間負荷=重い` かつ `インパクト=大` の小タスクを午前に割り当て |
| 作業開始時 | `Status` → `着手中`。15分経っても進まなければ先輩に質問 |
| 作業完了時 | `実時間（分）`・`差異理由` を入力 → `Status` → `完了` |
| 夕方 | 翌日の小タスクに `予想時間` を入力。`保留` は理由をコメントに残す |
| 大タスク完了時 | 振り返り欄を記入。工数サマリーを確認 |

### 優先順位の決め方

```
優先度（目安）= インパクト（大=3, 中=2, 小=1）× 緊急度 ÷ 時間負荷
```

| 状況 | 対応 |
|------|------|
| 重要かつ緊急 | 即日着手 |
| 重要だが緊急でない | 今週の作業ビューで計画的に実施 |
| 緊急だが重要でない | 簡略化 or 80点で先に見せる |
| 重要でも緊急でもない | やらない |

### 運用上の注意

- 大タスクの必須3項目は **Issue 本文** で管理する
- 工数は **小タスク単位** で記録する
- `保留` にしたら **理由をコメント** に残す
- Sub-Issue の親子関係を崩さない（小タスクを大タスク直下に作らない）
- 振り返りは次の大タスク作成時に前回分を参照する
